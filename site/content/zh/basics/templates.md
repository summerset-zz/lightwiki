模板（macro）是正文里的占位写法，构建时被替换成别的内容。写法是双层花括号加名字，带参数时后面跟一对圆括号。

主题包 `@lightwiki/theme-default` 只带两个模板：`catalog` 和 `pages`。没有 `note`、`card`、`glossary`、`warning` 这一类。

## 内置模板只有两个 {#builtin}

示例站上那些小卡片、提示框、术语列表，都是各自仓库在 `macros/` 里自己写的。装完 cli 直接建站，能用的名字就这两个。

用别的名字会落进未定义模板，处理方式在最后一节说明。

## 分类列表 {#catalog}

`{{catalog}}` 不接受参数，列出全部分类，每行一个 markdown 列表项：

```md
- [语法](/categories/syntax/)（3 篇）
```

没有分类时输出一句 `暂无分类。`。分类数据来自站点配置里声明过的分类，没声明的排在后面。

## 页面列表 {#pages}

`{{pages(...)}}` 列出全站页面，每行一个列表项 `- [标题](地址)`。三种用法：

| 写法 | 列出什么 |
|---|---|
| `pages()` | 全站全部页面 |
| `pages(section: guide)` | 某个分组下的页面 |
| `pages(category: syntax)` | 某个分类下的页面 |

`section` 和 `category` 可以同时写，两个条件一起筛。没有匹配时输出一句 `（没有匹配的页面）`。

排序沿用站内既有顺序（section → order → slug），不用自己排。一次构建只有一份内容目录，所以不需要按语言过滤。

## 参数的写法 {#args}

| 规则 | 说明 |
|---|---|
| 逗号分隔 | 多个参数用 `,`，空格不算分隔符 |
| 命名参数 | 写 `键: 值`，冒号。不要写 `key="value"` 或 `key=value`。键只认 ASCII 标识符（字母或下划线开头），中文键会被当成位置参数 |
| 引号 | 值可以用双引号、单引号或反引号包起来，引号里的逗号不会被切开 |
| 数字 | 纯数字的位置参数会转成 number，其余都是字符串 |
| 括号 | 按深度配对，值里可以再放一对括号 |

```md
{{pages(section: guide, category: syntax)}}
```

括号里的内容先被切成字符串，模板拿到的是字符串本身，不携带任何 markdown 结构。

它最后有没有结构，要看模板把参数写进产出之后，产出又过了一遍 markdown 解析。

## 模板文件的位置 {#location}

模板文件放在内容仓库的 `macros/` 目录，一个 `.eta` 文件一个模板，文件名去掉 `.eta` 就是模板名：

| 文件 | 调用的写法 |
|---|---|
| `macros/quote.eta` | `{{quote}}` |
| `macros/related.eta` | `{{related(...)}}` |

目录名叫 `macros` 是历史原因。正文里一律叫模板，但目录名不能改。

内容仓库的 `macros/` 优先于主题包自带的，同名会覆盖。想改 `catalog` 的输出，建一个 `macros/catalog.eta` 就行。

模板名大小写不敏感，`{{Catalog}}` 和 `{{catalog}}` 是同一个。内容仓库里没有 `macros/` 目录也完全正常。

## 模板能拿到的字段 {#context}

模板通过 `it` 拿到上下文，字段固定这几个：

| 字段 | 是什么 |
|---|---|
| `it.args` | 位置参数数组，元素是字符串或数字 |
| `it.named` | 命名参数对象 |
| `it.page` | 当前页，与皮肤里的 `page` 是同一个对象，有 `title`、`url`、`slug`、`categories`、`section` 等 |
| `it.site` | 全站信息，与皮肤里的 `site` 是同一个 |
| `it.lang` | 当前语言，如 `zh` |
| `it.addCategory(名字)` | 把当前页登记到某个分类，等于临时加了一条 `categories` |
| `it.macro(名字, ...参数)` | 在模板里调用另一个模板，返回已经渲染好的片段 |

## 自己写一个模板 {#write}

`macros/quote.eta`，把第一个参数包成引用块，署名放在第二行：

```eta
<%
// 第一个位置参数是引文，by 是署名，link 是署名指向的地址。
const text = it.args[0] ?? '';
const by = it.named.by ?? '佚名';
const link = it.named.link ?? '';
const credit = link ? `[${by}](${link})` : by;
%>
> <%~ text %>
>
> 出自 <%~ credit %>
```

正文里这样调用，整行只放这一处：

```md
{{quote(`页面身份是文件名，不是标题。`, by: 结构说明, link: /start/structure)}}
```

产物是一段引用块，第一行是引文，第二行是署名。

两处 `<%~ %>` 是必要的：引文里可能出现 `&` 或 `<`，换成 `<%= %>` 会被转成实体。调用独占一行，产出才会按块级解析成引用块。

## 产出的是 markdown {#markdown}

模板的返回值会被当成 markdown 再解析一遍，和页面正文走同一条管线。`**粗体**`、`[[双链]]`、再调一个模板都能用。

代价是要像写正文那样小心 `*`、`_`、`[` 这些字符。这也是 MediaWiki 的心智模型：模板写的是 wikitext，不是 HTML。

模板是同步执行的，里面不能 `await`。

## 输出转义 {#escape}

模板引擎默认开启 HTML 自动转义：

| 语法 | 行为 |
|---|---|
| `<%` | 纯逻辑行，不出字 |
| `<%= 值 %>` | 输出，并把 `<` `>` `&` 转成实体 |
| `<%~ 值 %>` | 原样输出 |

要输出 HTML 片段，或者内容里本来就有 `&` `<` `>`，必须用 `<%~ %>`。用 `<%= %>` 得到的是 `&lt;b&gt;` 这种字样，页面上会原样显示出来。

区分三者的只是 `<%` 后紧跟的那个字符，拆开写就失效了。

## 行内与块级 {#level}

模板写在段落中间时按行内解析，产物只当一行文字。整行只有一个模板调用、前后没有别的字符时按块级解析，产物可以是一段、一个列表、一张表格。

想输出 `<div>` 这类块级元素，必须让调用独占一行，否则会被塞进 `<p>` 里。

## 出错时的表现 {#failures}

未定义模板怎么显示，由站点配置的 `macros.undefined` 决定：

| 取值 | 产物 | `wiki check` |
|---|---|---|
| `'show'`，默认 | 原样显示 `{{名字}}` | 算失败 |
| `'hide'` | 整段不显示 | 只提示，不算失败 |
| 一个函数 | 返回值当纯文本插入 | 只提示，不算失败 |

写函数的写法只在 `wiki.config.ts` 是代码时可用。三种情况构建时都会在终端给出提示，不会静默通过。

循环引用会报 `macro cycle: a -> b -> a`。嵌套超过 20 层报错，正常用不到这么深。模板里有语法错误时会把原因打到终端：行内调用按上面那张表回退，整行独占的块级调用出错时，原文会以纯文本段落留在页面上。

正文的其它写法见 [Markdown 与扩展语法](/basics/markdown)，页面开头的字段见 [frontmatter](/basics/frontmatter)。
