# 模板语法支持

> 状态（2026-11-15）：内链、宏、上下文、分类均已实现。实际写法见 [`examples/mini`](../examples/mini)——那是一份用轻维基自己的语法写的手册，也就是这个仓库的文档。
> 本文保留需求原文，并在每节后面记评估与决定。

---

## 一、内链

### 需求

由于用户可能是从 mediawiki 来的，他们熟悉的写法是：

```
[[target page title]]

[[target page title|text]]

[[/target subpage]]
```

但这相当于要建立一个 title → page 的映射关系，可能得从 frontmatter 来。此外会出现撞标题的情况，得找地方警告用户哪两个文件撞了。

### 评估

**可行，但有一个架构前提。** 解析 `[[标题]]` 意味着渲染第 100 页时要能看见第 200 页的标题，所以不能边扫描边渲染——必须先扫完整个站、建好索引、再统一渲染。这个改动已经完成（`content.ts` 现在是「扫描 → 建索引 → 渲染」三阶段）。

**真正的风险是身份耦合。** MediaWiki 敢用标题当链接键，是因为在那边**标题就是页面身份**（标题即 URL），改名还有 redirect 兜底。我们的身份是文件名（slug），标题是给读者看的、随时会改的字段。改标题 → 所有 `[[旧标题]]` 断掉，这是必然代价。

因此解析顺序定为 **先 slug、再标题**：

| 写法 | 命中方式 | 稳定性 |
|---|---|---|
| `[[gsub-gpos]]` | slug（文件名） | 高，只有改文件名才断 |
| `[[GSUB / GPOS 详解]]` | 标题 | 中，改标题就断 |

同一条语法支持两种目标，靠「先查 slug 表、再查标题表」区分，不需要额外标记。

**撞标题必须报错而不是取第一个。** 两个页面同名时 `[[同名]]` 语义不明确，静默取第一个会让作者以为链对了。所以 `wiki check` 把标题重复列为**失败项**，并指出撞在一起的是哪几个文件。

**`[[/target subpage]]` 不支持。** MediaWiki 的子页面是层级路径（`/sub` 相对当前页），我们的 slug 里的 `/` 只是目录分隔，没有「父页面」概念。猜一个语义不如明确拒绝。

### 决定

- 支持 `[[目标]]` 与 `[[目标|显示文字]]`，目标先按 slug、再按标题解析；
- 目标里可以带 `#锚点`；
- 标题归一化：NFC + 折叠空白 + 大小写不敏感；
- 撞标题 = 错误；未命中 = 未解析内链（与红链同级，`--strict` 时失败）；
- 不支持相对子页面引用。

## 二、宏（内容模板）

### 需求

MDN 的内容仓库用过一种模板语法，类似：

```
{{glossary("Percent-encoding", "percent-encoded")}}
```

代表传给 glossary 两个参数，剩下交给模板处理。而对 mediawiki 用户来说更熟悉的是 `{{templatename|param1|param2=value2}}`。考虑用 MDN 那种函数式的。待定：

- 模板怎么写？用 md 还是 html？
- 参数怎么表示？MediaWiki 是序号参数 `{{1|fallback}}` 与命名参数 `{{param2|fallback}}`。

### MDN 的实际使用情况

统计 `mdn/content/files/en-us/web/css`（1285 个文件）：

- **宏调用 26241 处**，平均每文件 20 处；
- `cssxref` 一个宏 17158 次，其余是 `EmbedLiveSample`（1953）、`htmlelement`、`Specifications`、`Compat`、`Glossary`…；
- 形态有三种：**无括号** `{{Specifications}}`、列位置参数 `{{glossary("a", "b")}}`、反引号原样字符串 ``{{CSSSyntaxRaw(`x = y`)}}``；
- 含 `=` 的调用**全部**是反引号字符串内部的等号（`example = bold <length>`），说明 MDN 实际上没在用命名参数。

结论：宏不是边角功能，是内容基础设施。语法必须同时吃下这三种形态，否则真实语料迁移不过来。

### 决定

- **语法**：`{{名字}}`、`{{名字(位置参数, …)}}`、``{{名字(`原样`)}}``；命名参数写成 `键: 值`，解析但 v1 不强制；
- **函数式而非管道式**：管道式（`{{名|a|b=1}}`）在参数里出现 `|`、`,` 时歧义多，函数式配上引号更明确；
- **宏用 Eta 写，产出的是文本（markdown / wikitext），不是成品 HTML 片段**。理由：这就是 MediaWiki 的心智模型 —— 模板展开是“把文本插进去”，然后整页统一解析。所以在宏里可以直接写 `**粗体**`、`[[双链]]`、列表，甚至再调别的宏。
- **展开用解析器而不是正则**：在 markdown-it 的 block / inline 规则里把展开结果哏回 `md.block.parse` / `md.inline.parse`。因此代码块与行内代码天然免疫，不需要 `<nowiki>` / `<pre>` 这类逃生舱（KumaScript 是文本级替换，必须靠它们规避）。
- **宏必须是同步的**。markdown-it 的渲染管线不允许 `await`，所以宏文件在构建前全部预读进内存，模板里不能有 `await`。
- **两条规则**：整行只有一个宏时走块级解析（可以产出列表、表格），否则走行内解析（只能产出行内内容）。这是 markdown 本身的边界，不是我们加的。
- 宏名大小写不敏感（MDN 里 `Glossary` 与 `glossary` 并存）。
- **宏可以组合**：模板里直接写 `{{另一个宏}}` 就行，展开结果会继续被解析；也可以用 `it.macro("名字", 参数…)` 拿到“已渲染、不再参与解析”的字符串。循环引用与超过 20 层嵌套会被拦下并报错。
- **上下文对象而不是魔术字语法**：`it.page`（当前页）与 `it.site`（全站，含 `pageCount`、`pages[]`、`generatedAt`、`config`）是布局与宏共用的同一套对象。MediaWiki 的 `{{PAGENAME}}` 在这里就是 `it.page.slug`——不需要额外语法，因为它本来就是代码。
- **一个必须知道的差异**：宏执行时本页的 `html` / `headings` 还在生成中，所以**宏拿不到这些字段**（布局可以）。想要「根据正文生成目录」这类能力，只能放在布局层做。

## 三、分类

### 需求

页面本身的分类放 frontmatter 里；「模板」要能够给页面添加分类；页面可以指定使用哪个分类的列表作为边栏；分类页在编译时静态生成。

### 设计（已实现）

- **分类的键用 ASCII slug，显示名放站点配置**：

  ```ts
  categories: { linguistics: '语言学', formats: '字体格式' }
  ```

  页面写 `categories: [linguistics]`。理由是 URL 要稳定、要能翻译；中文分类名直接进 URL 会带来编码与改名双重问题。
- **宏登记分类已经打通**：渲染上下文里有 `addCategory()`，宏调用它就能给当前页加分。收上来的分类挂在页面对象上。
- **分类页在全部页面渲染完之后生成**。这一点与现有流程天然兼容——`build` 本来就是「渲染完所有页 → 再生成目录页」。
- **边栏**用 frontmatter 指定：`sidebarCategory: linguistics`，主题在 `it.page` 里拿到分类成员列表。
- 分类成员列表需要**先收集再渲染**，所以分类页不能与内容页同时输出；页面的边栏若依赖分类成员，也必须在第二轮渲染。这是本轮唯一会改变构建流程顺序的地方。

实现结果：分类页在内容页循环之后生成；侧栏用的是渲染完成后的 `page.categories`（因此宏 `addCategory` 登记的分类也能算进去）。`it.site.categoryList` 只统计「实际被用到」的分类，声明了但没页面的不会出现在目录页里。

## 四、命名

### 需求

有了内容模板之后，页面模板要不要改名以避免混淆？

### 决定

两个词从此固定，任何文档都不单独使用「模板」二字：

| 名字 | 目录 | 是什么 | 谁写 |
|---|---|---|---|
| **布局**（layout） | `layouts/*.eta` | 整页骨架，包含 `<html>`、侧栏、目录 | 主题作者 / 站点所有者 |
| **宏**（macro） | `macros/*.eta` | 正文里 `{{…}}` 调用的片段，产出 HTML 片段 | 内容作者 / 主题作者 |

选「宏」而不是「模板」：MediaWiki 用户说「模板」指的是 `{{…}}` 那个东西，MDN 那边叫 macro，两边都能对上；而「模板」这个词在我们的语境里已经被布局占用了。
