宏定义放在内容仓库的 `macros/` 目录，主题包也可以提供，内容仓库优先。名字大小写不敏感。

## 三种调用形态 {#forms}

```md
{{note("整行一个宏")}}
{{glossary("基线", "baseline")}}
{{glossary(`原样字符串`)}}
```

- 无参数：`{{宏名}}`
- 位置参数：`{{宏名(参数, "参数")}}`
- 反引号里的内容原样保留，不处理引号与逗号
- 命名参数写成 `键: 值`，会解析，但 v1 不强制使用

## 主题自带的目录宏 {#catalog}

首页或任何一页需要「目录」时，不用手写：

| 写法 | 产出 |
|---|---|
| `{{catalog}}` | 所有分类，带页面数与链接（页面数是该分类的篇数） |
| `{{pages(section: syntax)}}` | 某个分组下的页面列表 |
| `{{pages(category: demo)}}` | 某个分类下的页面列表 |
| `{{pages()}}` | 全站全部页面 |

参数用**命名参数**（`键: 值`），不是 `key="value"`；写错了会被当成位置参数，什么也过滤不出来。

它们产出的都是 markdown 列表，样式交给站点自己的 CSS。本页所在站点的首页用的就是这两个宏：

```text
{{catalog}}
```

```text
{{pages(section: reference)}}
```

## 宏没定义怎么办 {#undefined}

内容经常是从别处搬来的，原来站点自带的宏不一定跟着过来。这种「未定义的宏」怎么落地由站点配置决定：

```ts
// wiki.config.ts
export default {
  // 默认：保留 {{原文}}，一眼能看出漏了什么
  macros: { undefined: 'show' },
  // 或者：直接删掉
  // macros: { undefined: 'hide' },
  // 或者：自己决定（返回值当纯文本插入，不会再走一遍 markdown）
  // macros: { undefined: (name, raw) => `[缺失的宏：${name}]` },
};
```

三种都不影响构建能不能过，但**都会在构建输出里报一行提示**（几处、怎么处理的），`wiki check` 也照旧列出来。沉默才是真问题。

一个小区别：选默认的 `'show'` 时，`wiki check` 把未定义宏算**错误**（露花括号通常是漏搬了）；显式选了 `'hide'` 或给了函数，说明你知道自己在做什么，就只当提示。

## 宏产出的是文本 {#text}

展开结果会跟正文一样再过一遍解析器，所以宏模板里可以直接写 markdown：

{{md-demo}}

这也意味着宏作者要像写正文那样注意 `*` `_` `[` 这些字符——它们会被当成格式标记。这一点和 MediaWiki 一样。

## 宏调用宏 {#compose}

模板里直接写 `{{另一个宏}}` 就行，展开结果会继续被解析：

{{chain}}

也可以用 `it.macro("名字", 参数…)` 拿到「已渲染、不再参与解析」的字符串：

{{card("基线", "card 的正文。标题由 glossary 宏生成。")}}

循环引用和超过 20 层的嵌套都会被拦下，并在 `wiki check` 里报错，页面上保留原文。

## 代码块里不会展开 {#escape}

围栏代码块与行内代码里的 `{{…}}` 不会被当成宏：

```
{{note("这行不会执行")}}
```

原因是我们在解析器的规则层处理，而不是对整段文本做正则替换。
